PASO 1: PREPARAR LA BASE (una sola vez)
---------------------------------------
  cd ~/Downloads/ProyectoBD
  mysql -u root -p < usuarios_finales.sql

Se puede volver a ejecutar sin problema: lo que ya existe no se vuelve a crear.
Si ya lo habías corrido antes, córrelo otra vez para que se cree la tabla Bitacora
y los usuarios nuevos.

El script crea la tabla Usuario con estos usuarios finales:
  admin   / admin123
  luis    / luis123
  jason   / jason123
  alfredo / alfredo123

También crea la tabla Bitacora y el usuario de MySQL APP_LIGA, que es con el que la
aplicación se conecta por dentro.

IMPORTANTE: el script agrega la columna ID_Usuario a las tablas existentes, así que
las tablas (Estado, Posicion, Patrocinador, etc.) deben existir antes de correrlo.

Para tener datos con qué probar (los menús de Contrato y Alineación necesitan equipos, jugadores y partidos):
  mysql -t -u root -p < datos_prueba.sql


PASO 2: EJECUTAR
----------------
  cd ~/Downloads/ProyectoBD
  sh ejecutar.sh

El script busca el conector en Lib/ o en la raíz del proyecto.

O a mano (desde la raíz del proyecto):
  javac -encoding UTF-8 -cp Lib/mysql-connector-j-26.7.0.jar -d out Main.java conexion/*.java modelo/*.java vista/*.java vista/tablas/*.java
  java -cp out:Lib/mysql-connector-j-26.7.0.jar Main

Si tu conector tiene otro nombre, cámbialo en ejecutar.sh.

VALIDACIONES DE LAS TABLAS PADRE (Estado, Posicion, Patrocinador)
------------------------------------------------------------------
  ID        Opcional al insertar (MySQL lo asigna). Si se escribe, debe ser un entero mayor que 0.
            No puede quedar vacío al actualizar ni repetirse.
  Nombre    Obligatorio, máximo 20 caracteres.
  Actualizar y Eliminar piden seleccionar antes un registro de la tabla.


VALIDACIONES DE LAS TABLAS HIJAS
--------------------------------
Todos los campos con * son obligatorios. Las llaves foráneas se eligen con un menú desplegable que
muestra solo los registros que existen en la tabla padre, así nunca se guarda un ID que no existe.
Los menús se vuelven a leer cada vez que abres la pestaña (ahí aparece lo que agregaste en otra pestaña).
Si alguien borra el registro padre mientras tanto, MySQL lo rechaza, sale el aviso y el menú se actualiza.

  Ciudad       Nombre obligatorio, máximo 20 caracteres. Hay que elegir el estado.
  Contrato     Hay que elegir equipo y patrocinador. Las fechas deben ser reales y con formato AAAA-MM-DD.
               La fecha de fin no puede ser antes que la de inicio.
               Un equipo no puede tener dos contratos con el mismo patrocinador (llave primaria).
  Alineacion   Hay que elegir partido, equipo, jugador y posición. El orden al bat va del 1 al 9 (CHECK).
               El equipo tiene que jugar ese partido (ser local o visitante).
               El jugador tiene que ser de ese equipo.
               Un jugador aparece una sola vez por partido (llave primaria).
               En un mismo partido y equipo no se repite el turno al bat ni la posición (UNIQUE).


AL ELIMINAR (en todas las tablas)
---------------------------------
Antes de borrar se revisa si otras tablas tienen registros ligados por llave foránea.
Si los hay, sale una advertencia que dice en qué tablas y cuántos, y no se borra
(por ejemplo, un estado que todavía tiene ciudades). Si no los hay, pide confirmación.

CÓMO AGREGAR OTRA TABLA
-----------------------
Tabla padre (solo ID y nombre), ejemplo: copia PanelPosicion.java y cambia la tabla y las columnas:

   super("Posicion", "ID_Posicion", "Nombre_Posicion", "Nombre de la posición", 20);

Tabla hija (con llaves foráneas), ejemplo para Equipo: hereda de PanelBaseHija y declara sus campos
en el orden en que quieres que salgan:

   public class PanelEquipo extends PanelBaseHija {
       public PanelEquipo() {
           super("Equipo");
           llaveAutomatica("ID_Equipo");                       // llave primaria que asigna MySQL
           texto("Nombre_Equipo", "Nombre del equipo", 20);    // VARCHAR(20)
           menu("ID_Ciudad", "Ciudad", "SELECT ID_Ciudad, Nombre_Ciudad FROM Ciudad ORDER BY Nombre_Ciudad");
           armarPantalla();
       }
   }

   Lo que puede declarar una tabla hija:
     llaveAutomatica(columna)                  llave primaria con AUTO_INCREMENT
     menu(columna, etiqueta, consulta)         llave foránea (el SELECT regresa el ID y el texto que se ve)
     llaveMenu(columna, etiqueta, consulta)    llave foránea que también es parte de la llave primaria
     texto(columna, etiqueta, maximo)          texto obligatorio
     numero(columna, etiqueta, minimo, maximo) número entero obligatorio dentro de un rango
     fecha(columna, etiqueta)                  fecha obligatoria AAAA-MM-DD
     avisoRegla(nombreDeLaRegla, mensaje)      mensaje propio si falla un UNIQUE, un CHECK o la llave primaria (PRIMARY)
   Y si necesita reglas de más de un campo, sobreescribe reglaExtra() (ver PanelContrato y PanelAlineacion).

En los dos casos, regístrala en VentanaPrincipal.java, dentro de mostrarPrincipal():

   pestanas.addTab("Equipos", new PanelEquipo());

   (y su import: import vista.tablas.PanelEquipo;)
